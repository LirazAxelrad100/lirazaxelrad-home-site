# Project: Liraz Axelrad personal site

## What it is
Personal site for Liraz Axelrad — product management + meditation + migration/life-transitions mentor. Astro + TypeScript + Tailwind CSS. Two independent language versions, not translations of each other:
- Hebrew (RTL) at `/` — primary/default language.
- English (LTR) at `/en`.

Both use the same menu-driven interactive homepage (click a menu item to open an inline info panel — no page navigation) built in `src/components/HomeMenu.tsx`, mounted as the site's only large client island (`client:load`) on `src/pages/index.astro` / `src/pages/en/index.astro`. Everything else on the site is static HTML with zero shipped JS, except the small `ContactForm.tsx` island on the Contact page.

Menu items live as Astro content collections — one Markdown file per item per locale (`src/content/menu/he/*.md`, `src/content/menu/en/*.md`), schema in `src/content.config.ts`. Adding/removing/reordering a menu item is adding/deleting a file or changing its `order` frontmatter number — no code editing required.

**Every menu item also has its own real page** (e.g. `/about`, `/pm`, `/meditation`, `/migration`, `/berlin`), rendered from that same Markdown file's body via a shared dynamic route (`src/pages/[item].astro`, `src/pages/en/[item].astro`) and `src/components/pages/MenuItemContent.astro`. The body is just paragraphs separated by a blank line — the **first paragraph** is pulled out (`src/lib/menu.ts`, `firstParagraph()`) and shown as the teaser in the homepage's grey panel; the full page shows every paragraph. So writing copy for an item is just writing paragraphs into its `.md` file — no separate excerpt field to keep in sync. Exception: English's "Writing" item (`src/content/menu/en/writing.md`) is excluded from this — its `href` points at the real `/en/writing` list instead, so it doesn't get one of these generic pages.

All other copy (name/tagline, Writing posts, Contact labels, footer) lives in `src/data/site.he.ts` / `site.en.ts` (shape in `src/data/types.ts`). About no longer has its own entry there — it's just another menu item now.

Original high-fidelity design prototype (static `.dc.html` files + handoff README) is preserved in `design/` for reference.

## Key decisions
- **Claude writes the code; Liraz reviews/tests in browser and handles all git commands herself** (add/commit/push) — for her portfolio, and her stated preference for this project.
- **On mobile, homepage menu items navigate straight to their own page instead of opening the teaser panel**, decided 2026-09-01 (commit `d8520e8`). Liraz spotted that below `md` the yellow panel renders *below* the menu, off-screen — so tapping an item looked like nothing happened, and she worried visitors would bounce. Options weighed were (a) navigate directly, or (b) replace the menu with the panel. Chose (a): the panel only ever holds the item's **first paragraph plus a "read more" link**, so (b) would still cost a second tap to reach content *and* would need a new back affordance to return to the other menu items. Implementation is deliberately tiny — each item was already a real `<a href={item.href}>`, and `HomeMenu.tsx`'s `onClick` simply skips `e.preventDefault()` when `window.matchMedia("(min-width: 768px)")` doesn't match, letting the browser navigate. 768px is Tailwind's `md`, the same breakpoint where the layout goes side-by-side, so the panel only opens when there's actually room beside the menu. Verified both ways: 375px navigates to `/pm`, 1280px stays home and opens the panel. Bonus: the links now work without JS. Desktop hover/click behavior is untouched — don't "unify" the two.
- **Footer stacks and centers below `md`; every footer link is `whitespace-nowrap`**, fixed 2026-09-01. Hebrew's footer has 6 links (contact + 4 socials + language mirror) vs English's 5, and at 375px labels like "English site" and "צרו קשר" were breaking *inside themselves* across 2 lines. Note the real fix was **not** a smaller font (Liraz's first instinct) — shrinking text keeps the mid-label breaks and just makes them harder to read. `Footer.astro`'s row is now `flex-col items-center text-center md:flex-row md:justify-between md:text-start`, the link group has its own `gap-x-4 gap-y-2 md:gap-5`, and each `<a>` is `whitespace-nowrap`. Desktop is byte-for-byte the same layout as before; the homepage's one-viewport-no-scroll constraint still holds (the fix actually *reduces* footer height, since 2-line labels collapse to 1).
- **Email delivery is fully working as of 2026-09-01 — `hello@lirazaxelrad.com` receives, and the contact form delivers.** Verified end to end by submitting the live English form and receiving the mail in Gmail. The setup has two independent halves, and keeping them separate is deliberate:
  - **Receiving — Cloudflare Email Routing** on the **apex**: MX `route1/2/3.mx.cloudflare.net`, SPF `v=spf1 include:_spf.mx.cloudflare.net ~all`, plus a Cloudflare-managed `cf2024-1._domainkey`. Rule: `hello@lirazaxelrad.com` → Liraz's personal Gmail. Those records are **locked** in the Cloudflare UI — don't edit them. Her Gmail lives only in Email Routing's config, never in site code or UI, which is how she wants it.
  - **Sending — Resend**, verified for `lirazaxelrad.com`, region Ireland (`eu-west-1`), with its records on the **`send.` subdomain**: MX `send` → `feedback-smtp.eu-west-1.amazonses.com`, TXT `send` → `v=spf1 include:amazonses.com ~all`, plus `resend._domainkey` (DKIM) and `_dmarc` (`v=DMARC1; p=none;`) on the apex.
  - **The feared SPF collision never happened** — because Resend puts its SPF on `send.`, not the apex, the two systems coexist untouched. ⚠️ **Keep "Enable Receiving" OFF in Resend**: turning it on would add Resend MX records to the apex and break the `hello@` forwarding. Chose **Manual setup** over Resend's "Auto configure" precisely to keep control here, and to avoid granting Resend standing write access to the DNS.
  - `contact.ts` now sends `from: "Website contact form <noreply@lirazaxelrad.com>"`. `noreply@` deliberately has no inbox — `replyTo` is the visitor's address, so hitting Reply in Gmail reaches them.
  - The footer `mailto:` link was **re-enabled** the same day (it had been turned off in `c4f1e76` because the address went nowhere), so `hello@` is now clickable again on every page in both locales.
  - The contact form's topic dropdown defaults to a **placeholder** ("Select your topic" / "באיזה עניין?") with an empty value, instead of pre-selecting the first real option. An unpicked topic therefore arrives as `""`, not `undefined` — which is why `contact.ts` uses `topic || "No topic selected"` rather than `??`. Watch that distinction if the field is ever reworked.
- **Analytics and SEO, built 2026-09-03.** Everything below is code that is already merged; the two dashboard steps are listed under "What's next".
  - **Analytics: Vercel Web Analytics** (`@vercel/analytics`, `<Analytics />` in `HtmlShell.astro`). Chosen over Plausible/Fathom (paid) and GA4 (heavy, cookie-consent banner needed in the EU) because it is free on the Hobby plan already in use, needs no cookie banner, and is one line of code. Limit is 50k page views/month. ⚠️ **It only reports once Web Analytics is switched on in the Vercel project** — until then the script 404s silently and no data appears.
  - **Open Graph / Twitter cards** — previously absent entirely, so every shared link rendered as a bare URL. `HtmlShell.astro` now emits the full `og:*` / `twitter:*` set, plus `<meta name="author">`.
  - **Social-share images are generated, not hand-made**: `node scripts/make-og.mjs` writes `public/og-{en,he}.png` (1200×630) from her About headshot plus the name/tagline, in the site palette. Rerun after changing the name, tagline or photo; output is deterministic. **Hard-won detail: the SVG renderer sharp uses (librsvg/pango) already does right-to-left reordering correctly, but ONLY if left alone** — adding `direction="rtl"`, or pre-reversing the Hebrew string, both produce mirrored gibberish. Right-alignment is done with `text-anchor="end"` and nothing else. Rubik/Heebo aren't installed system-wide and Fontsource ships woff2 only (which fontconfig can't read), so the cards render in Helvetica/Arial Hebrew — fine at social-card sizes, and not worth installing fonts over.
  - **Structured data (`src/lib/seo.ts`)** — `ProfilePage` + `Person` on both homepages, `BlogPosting` on each English post, `Blog` on the writing index. This is the piece that gives Google and AI answer engines an *entity* to attach her name, role, Berlin location and social profiles to, rather than loose words. `sameAs` deliberately lists all four profiles including Substack, even on English pages where the footer omits it — `sameAs` proves identity, it isn't a display list.
  - **Per-page meta descriptions** — every page used to repeat the same site-wide description. Item pages and writing posts now derive theirs from their own opening paragraph via `toDescription()` (strips Markdown, cuts at a word boundary under 160 chars); Contact uses its intro; the writing index and tag pages have written ones.
  - **Canonical URLs are now trailing-slash-free** (root aside), matching `sitemap.xml` and every internal link. Astro hands `Astro.url.pathname` with a trailing slash at build time, so `HtmlShell.astro` normalises it in one `absolute()` helper used for canonical, hreflang and og:image alike. Before this, canonical said `/en/pm/` while the sitemap said `/en/pm` — the same page under two URLs.
  - **`alternateHref` is now `string | null`.** English writing pages used to declare a Hebrew "alternate" pointing at Hebrew's placeholder `/writing`, which is not a translation of anything. Passing `null` emits no hreflang links at all — correct for a page that exists in one language only. Also added `hreflang="x-default"` (→ the Hebrew URL, since Hebrew is the site's default) wherever a real pair does exist.
  - **Hebrew's placeholder `/writing` pages are `noindex` and out of the sitemap.** They still hold Lorem Ipsum and aren't linked from the Hebrew menu; letting Google index them would have been a real negative. Undo the `noindex` prop and restore the sitemap routes if Hebrew Writing is ever built for real.
- **Google Search Console set up 2026-09-03 — verified, sitemap submitted.** Four details worth keeping, all of which cost a step to discover:
  - **Property type is Domain, not URL prefix.** One property covers Hebrew (`/`) and English (`/en`) together, plus `www`/non-`www` and http/https. URL prefix would have meant maintaining two properties. The `hreflang` tags shipped the same day are what tell Google the two locales are the same site in two languages.
  - **Verification is a TXT record at the apex, added by hand in Cloudflare.** Google offered a one-click "authorize Google to access your Cloudflare DNS account" flow; declined it in favour of `Instructions for: Any DNS provider`, consistent with the same call made for Resend — no standing DNS write access for third parties. ⚠️ **That TXT record must never be deleted**, or Search Console access is lost. It sits alongside the Email Routing SPF record at `@`; multiple TXT records at the apex coexist fine, but never *edit* the SPF one.
  - **Google's verification token is visually truncated in its own input box** — the on-screen text ended `...M44cE` while the real value ended `...M44cEGu0kN8`. Always use its COPY button, never retype what's displayed.
